### [MINOR] semdb-storage — `/home/olafurbui/Projects/SMARTAGENT/crates/semdb/src/storage.rs`:306
**decode_record pre-allocates Vec::with_capacity(dim) from an untrusted length before bounds-checking bytes**
- Failure: A hand-crafted db file containing a record with a valid CRC over a body whose dim field = 0xFFFFFFFF but only a few trailing bytes -> Db::open -> Vec::with_capacity(4.29e9) -> allocation abort / OOM instead of the intended 'treat as corruption boundary and truncate'.

- Failure: Two clients hit two different dbs; the first triggers a cold open of a 500MB db -> the second client's handle() blocks on the registry lock for the full duration of the first db's read+replay, even though the two dbs are unrelated.

### [MINOR] gateway-fleet — `crates/gateway/src/server.rs`:570
**GLOBAL_DISPATCH token is consumed even when the per-agent gate then blocks, starving other idle agents**
- Failure: Agent A prompted 10s ago (via the work-chaser) so its per-agent gate is still cooling down. A's 120s heartbeat fires: GLOBAL_DISPATCH.allow() returns true and sets last=now, then per_agent.allow() returns false → A sends nothing. One second later idle agent B, which has pullable ready work and a clear per-agent gate, hits GLOBAL_DISPATCH.allow()==false and is blocked for up to 15s. The fleet's dispatch slot was wasted by an agent that could not act, delaying B's pickup.
- Fix: Check the per-agent gate first and only consume the global token when a prompt is actually going to be sent — e.g. `AUTONOMY && per_agent.allow() && GLOBAL_DISPATCH.allow()` combined with committing the timestamps only on the success path, or split allow() into a non-mutating peek plus an explicit commit performed right before child.command("prompt", ...).

### [MINOR] gateway-fleet — `crates/supervise/src/proc.rs`:102
**spawn_detached drops the Child and watch never wait()s → zombie/defunct process leak**
- Failure: A service crash-loops (or is restarted). Each death leaves a <defunct> process under the supervise pid; with backoff capped at 480s a crashing service leaks roughly one zombie every few minutes, and normal restarts leak one each. Over a long-lived watch these accumulate in the process table, consuming PIDs and cluttering ps until the supervisor itself exits.
- Fix: Reap children: either keep the Child handles and call try_wait() opportunistically in the watch loop, or install a SIGCHLD reaper (spawn `bash -c` wrapper, or double-fork so children reparent to init immediately), or set the disposition so exited children are auto-reaped. Simplest std-only path: retain the Child in a Vec and try_wait() each iteration to collect exited ones.

### [MINOR] tasks-workflow-hooks — `crates/tasks/src/worktree.rs`:278
**MergeLock stale-reclaim TOCTOU lets two waiters both hold the merge lock**
- Failure: After a prior holder crashes mid-merge (leaving a stale lock), two agents calling `tasks done` race the reclaim and both proceed to merge_isolated+ff-only against the shared main checkout. The isolated/ff-only design prevents base-branch corruption, but the second fast-forward fails (base moved) and that task's done is spuriously refused with 'worktree/branch preserved for manual merge' — defeating the lock whose whole purpose is to avoid exactly that. - Fix: Reclaim atomically: rename the stale lock to a unique temp and only proceed if the rename (not a separate remove) succeeded, or re-open O_EXCL and verify the pid/mtime you removed is the one you observed. Don't remove-then-create across a TOCTOU gap.

### [MINOR] browser-schedule-goal — `crates/browser/src/ws.rs`:111
**send_pong truncates the frame length for ping payloads >125 bytes, emitting a corrupt WebSocket frame**
- Failure: A CDP endpoint (or a non-conformant/MITM server on the ws:// socket) sends a ping frame with a 200-byte payload. `recv_text` calls `send_pong(&payload)`. Header byte = 0x80|(200 as u8)=0xC8, so the length field reads 72, but 200 payload bytes are written. The server consumes 72 bytes as the pong and parses byte 73 onward as a bogus frame, desyncing the stream and breaking the session.
- Fix: Reject (or cap) control frames whose length exceeds 125 in `read_frame`, and/or make `send_pong` truncate the echoed payload to 125 bytes and emit a correct single-byte length. Never form the length with a raw `as u8` cast.

### [MINOR] site-frontend — `scripts/_bundle.sh`:202
**bundle_verify checks the hash anywhere in SHA256SUMS, never binds it to the expected filename**
- Failure: A release directory whose SHA256SUMS lists `<hash>  other-file.tgz` (hash-reuse) makes verification of bundle.tar.gz pass even though no line binds that hash to bundle.tar.gz; and any MITM controlling the download URL swaps both tarball and SUMS and passes verification, so `install.sh --from https://...` installs an attacker-controlled bundle while printing no error.
