### [CRITICAL] security-secrets — `crates/sandbox/src/exec.rs`:145
**Sandbox secret-mask is trivially defeated by `umount` — master AEAD key exfiltrates**
- Failure: Agent runs (or prompt-injection forces) `sandbox run -- sh -c 'umount "$PWD/data/secrets"; cat data/secrets/secrets.key'`. Sandbox reports `isolated: namespaces`, stdout contains the raw master key; attacker decrypts the entire secret store.
- Fix: A removable tmpfs mask under a mapped-root payload is not a boundary. Drop CAP_SYS_ADMIN before exec (map `$@` to a non-root uid via a second uid_map / `setpriv --reuid` wrapper so it can't umount), or `pivot_root` into a minimal rootfs that never contains the sensitive paths. In pure std the honest fix is to stop treating the mask as a guarantee: keep the key reachable only through the semdb daemon socket (itself under masked .pi) and never leave key bytes on a path the payload can traverse.

### [MAJOR] security-secrets — `crates/sandbox/src/exec.rs`:174
**Sandbox reads the user's home-dir credentials (~/.ssh, ~/.aws, ~/.config/bw)**
- Failure: A sandboxed build/test step (or injected payload) runs `cat ~/.ssh/id_ed25519` / `cat ~/.config/bw/env` and exfiltrates SSH and password-manager credentials to the agent transcript — full account compromise — despite the tool advertising isolation for untrusted commands.
- Fix: The mask allowlist is a denylist that misses the real crown jewels. Either mask the entire home dir tree (mount tmpfs over $HOME, then bind only the workspace), or invert to an allowlist rootfs (pivot_root into a scratch root exposing only cwd + PATH bins). At minimum add ~/.ssh, ~/.aws, ~/.gnupg, ~/.config to the mask set and do not re-inject HOME pointing at the real home.

### [MAJOR] security-secrets — `crates/sandbox/src/exec.rs`:113
**Mask mount failure is swallowed while `isolated:true` is still reported**
- Failure: On a host where unprivileged tmpfs mounts are restricted, `sandbox run` reports `isolated: namespaces` but the .pi router key and secret store are readable by the sandboxed command — silent security-state corruption; no error, no warning.

### [MAJOR] security-secrets — `crates/secrets/src/store.rs`:83
**Key first-init race (no O_EXCL/lock) permanently corrupts stored secrets**
- Failure: Concurrent first-use: proc A `set api=…` (sealed K1) then writes K1; proc B writes K2 and `set db=…`. Later `secrets get --name api` returns permanently: 'secret failed authentication (tampered, wrong key, or corrupt)'. Silent data loss of the earlier secret.
- Fix: Create the key atomically with OpenOptions::new().write(true).create_new(true).mode(0o600).open(path); on AlreadyExists, re-read the winner's key. This closes both the last-writer race and the world-readable window (mode set at create time, not after).

### [MAJOR] code-intel-skills — `crates/codegraph/src/lang.rs`:280
**Non-Rust call extraction attributes call edges to functions in a different file**
- Failure: Repo with a.py (`def alpha():` at line 1, calls nothing) indexed before b.py (`beta()` at line 1, `def runner():` at line 2). ### [MAJOR] code-intel-skills — `crates/codeindex/src/regexlite.rs`:143
**regex-lite matcher has catastrophic backtracking (ReDoS): unbounded hang in `codeindex search -e`**
- Failure: Compiled the exact matcher and timed it: pattern `a*`x30 + `b` against a 40-char line of 'a' (no 'b') did not finish in 15s (timeout). A realistic wildcard search `@.*.*...*!` (20 `.*`) against a 60-char line with no `!` also timed out at 10s. Any such search hangs the tool indefinitely, blocking the searching agent/fleet with no way to cancel short of killing the process.
- Fix: Replace the backtracking engine with an iterative Thompson NFA simulation (linear time), or memoize visited (token_index, pos) states to make it polynomial, or enforce a hard cap on total match steps and return an error when exceeded. At minimum bound recursion depth and reject patterns with too many adjacent unbounded quantifiers.

### [MAJOR] telegram-evals-etc — `crates/telegram/src/inbound.rs`:141
**Unbounded thread + gateway-subprocess spawn per inbound message (DoS)**
- Failure: Combined with the mention allow-list bypass (finding 1), an attacker floods `@bot ...` messages from a group; every message spawns a thread and a long-lived gateway subprocess (each up to 90s, each potentially using GPU/inference). PIDs, memory, and file descriptors climb without bound -> host DoS. Even without the bypass, one chatty allowed user can exhaust the box.

### [MINOR] semdb-storage — `/home/olafurbui/Projects/SMARTAGENT/crates/semdb/src/storage.rs`:306

- Failure: A hand-crafted db file containing a record with a valid CRC over a body whose dim field = 0xFFFFFFFF but only a few trailing bytes -> Db::open -> Vec::with_capacity(4.29e9) -> allocation abort / OOM instead of the intended 'treat as corruption boundary and truncate'.

### [MINOR] gateway-fleet — `crates/gateway/src/server.rs`:570

### [MINOR] gateway-fleet — `crates/supervise/src/proc.rs`:102
**spawn_detached drops the Child and watch never wait()s → zombie/defunct process leak**
- Failure: A service crash-loops (or is restarted). Each death leaves a <defunct> process under the supervise pid; with backoff capped at 480s a crashing service leaks roughly one zombie every few minutes, and normal restarts leak one each. Over a long-lived watch these accumulate in the process table, consuming PIDs and cluttering ps until the supervisor itself exits.
- Fix: Reap children: either keep the Child handles and call try_wait() opportunistically in the watch loop, or install a SIGCHLD reaper (spawn `bash -c` wrapper, or double-fork so children reparent to init immediately), or set the disposition so exited children are auto-reaped. ### [MINOR] browser-schedule-goal — `crates/browser/src/ws.rs`:111
**send_pong truncates the frame length for ping payloads >125 bytes, emitting a corrupt WebSocket frame**
- Failure: A CDP endpoint (or a non-conformant/MITM server on the ws:// socket) sends a ping frame with a 200-byte payload. `recv_text` calls `send_pong(&payload)`. Header byte = 0x80|(200 as u8)=0xC8, so the length field reads 72, but 200 payload bytes are written.
